# Maintenance commands no longer start background jobs

- One-off `flask` commands (`backup-now`, `restore-backup`, `shell`, …) no longer start the web server's background jobs (backup schedule, update check, notifications, sync watcher). A restore no longer runs next to them; it previously did even inside the web container. The web server itself, including `flask run` in development, is unchanged.
- The language and theme switches redirect without a page body, and the pilot logbook, flights and documents lists only repeat valid sort and page-size values in their links (both reported by the new signed-in security scan; neither was exploitable).
- A number far too large for an id, page, year or period, in a page address or a form, is now ignored or answers "not found" instead of a server error (for example an id above 2,147,483,647, the database's limit); day/night landings that large are refused with a message. Reported by the signed-in security scan once it completed; not exploitable.

**Maintenance**
- Role-matrix test: a helper user that failed to sign in now fails at setup with the reason, and a wrong status shows where it redirected, so the rare unexplained failure seen once can be diagnosed if it recurs.
- Fuzzing: removed the two harnesses for the offline sync code deleted with offline editing (they failed the nightly fuzz run), and the test run now checks that every harness loads and that the fuzz workflow runs each one.
- Signed-in security scan: its attack phase is now time-limited (90 min) and skips generated downloads (track images, ZIP/PDF/CSV exports) and the language/theme switches (about 70% of its crawl), so it always produces a report (the first run found hundreds of signed-in pages and hit the 2-hour job limit), and it now also scans the pilot profile page, which a too-broad exclusion had hidden. Each run also scans one aircraft and the flights, logbook entries and reservations whose ID ends in one digit, rotating every run, instead of all of them (the same pages repeated, which kept it at about 40% of its checks).
- Tests: every page is now requested signed out and must send the visitor to sign in (or answer 401/404), apart from an explicit list of public pages; and a test confirms the URL-rewrite headers `X-Original-URL` / `X-Rewrite-URL` never change the page served. These check what two of the scan's rules could not (both reports were false alarms).
